## File Structure
<!-- FR-002: describe transport, client, resources, generated models, .graphql ops. -->

| Path | Role |
|------|------|
| `src/styrmin_sdk/client.py` | `StyrminClient` — public entry point; instantiates one resource per area. |
| `src/styrmin_sdk/_transport.py` | Internal HTTP + GraphQL transport over `httpx.AsyncClient`. |
| `src/styrmin_sdk/_queries.py` | `load_query(name)` helper that reads `graphql/<name>.graphql`. |
| `src/styrmin_sdk/exceptions.py` | `StyrminError` and typed subclasses raised on transport / GraphQL errors. |
| `src/styrmin_sdk/resources/` | One `*Resource` class per area; each method maps to one operation. |
| `src/styrmin_sdk/resources/_base.py` | `BaseResource`: `_check_graphql_errors`, `_parse` helpers. |
| `src/styrmin_sdk/graphql/*.graphql` | One operation per file; snake_case of the operation name. |
| `src/styrmin_sdk/graphql/_generated/` | Pydantic models regenerated by `uv run invoke generate`. **Never hand-edit.** |
| `tests/` | Unit and contract tests for the SDK. |

## Adding or changing a GraphQL operation
<!-- FR-003 + FR-004: explicit "regen is not enough" warning and full workflow. -->

> ⚠️ **Regenerating types is not enough.** Adding a `.graphql` file and running
> `uv run invoke generate` updates the Pydantic models under `_generated/`,
> but the SDK's Python surface (`client.py`, `resources/<area>.py`) does **not**
> auto-wire new operations. You must update the Python code by hand.

Step-by-step:

1. Create or edit a `.graphql` file under `src/styrmin_sdk/graphql/`. One
   operation per file. The operation **must** be named, and the file name
   **must** be snake_case of the operation name (e.g., `query GetCluster` →
   `get_cluster.graphql`). See the root `AGENTS.md` "GraphQL Queries" section
   for the repo-wide rules.
2. Regenerate the schema and SDK types from the repo root:

   ```bash
   uv run styrmin export graphql-schema schema.graphql
   uv run invoke generate
   ```

3. Validate:

   ```bash
   uv run invoke validate-graphql
   ```

4. Wire the operation into Python:
   - **Existing area** (e.g., clusters, deployments): add a method to the
     matching `*Resource` class in `src/styrmin_sdk/resources/<area>.py`.
     Use `load_query("<file_name>")`, call `self._transport.execute(...)`,
     then `self._check_graphql_errors(result)` and `self._parse(...)` (or
     `Outer.model_validate(result["data"])` for list-shaped responses).
   - **New area**: create a new resource module, add a `*Resource` class,
     and instantiate it in `StyrminClient.__init__` so it is reachable as
     `client.<area>`.
5. Add/extend tests under `python_sdk/tests/`. Mirror the new method's
   shape: positive case, error case (`extensions.code` mapping).
6. Run `uv run invoke format lint` before commit.

## Worked example
<!-- FR-009: show load_query() + Pydantic validation in concert. -->

From `resources/clusters.py`:

```python
async def get(
    self,
    cluster_id: str | UUID | None = None,
    cluster_name: str | None = None,
) -> GetClusterCluster:
    variables: dict[str, Any] = {}
    if cluster_id is not None:
        variables["clusterId"] = str(cluster_id)
    if cluster_name is not None:
        variables["clusterName"] = cluster_name
    result = await self._transport.execute(load_query("get_cluster"), variables)
    self._check_graphql_errors(result)
    return self._parse(GetCluster, result["data"], "cluster", GetClusterCluster)
```

The query `get_cluster.graphql` is loaded by name; the response is validated
against the generated `GetCluster` model and the inner `cluster` field is
returned as `GetClusterCluster`.

## Always Do / Ask First / Never Do
<!-- FR-005: SDK-specific boundaries, mirroring the root AGENTS.md structure. -->

### Always Do

- Run `uv run invoke validate-graphql` after touching any `.graphql` file.
- Regenerate types after any `.graphql` change: `uv run invoke generate`.
- Update both the `.graphql` file **and** the Python wiring in the same
  change — neither is automatic.
- Run `uv run invoke format lint` before commit.
- Write tests for new resource methods.

### Ask First

- Changes to the transport layer (`_transport.py`) — affects every operation.
- Changes that break the public client API surface (`StyrminClient` or
  any `*Resource` public method signature).
- New third-party dependencies in `python_sdk/pyproject.toml`.
- Reorganizing `resources/` (e.g., splitting or merging modules).

### Never Do

- Hand-edit anything under `src/styrmin_sdk/graphql/_generated/`.
- Inline GraphQL strings in Python — every operation lives in its own
  `.graphql` file and is loaded via `load_query()`.
- Add unnamed operations (`query { ... }`).
- Skip running `validate-graphql` after `.graphql` changes.
