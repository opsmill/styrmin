## Executive Summary

The spec solves a reported failure (#492) with the fix its author chose in #508, and the plan places the binding at the right points in each write path, which the research checked line by line. The main gap is the terms that a driver version gives a component: the plan binds them by name each time they are copied, but the clone request check reads the source's stored ids, so the check can accept a request that the flow then fails, and a rename still breaks a later driver-version change for those terms. Smaller gaps: the order of counterparts is defined in two ways that can conflict, the counterparts that already failed stay in the accepted ids, and some existing tests write names of deployments that do not exist and will start to fail. None of these needs a different design.
