## Behaviour

| Call | GraphQL variables sent | Result |
|------|------------------------|--------|
| `list_backups(deployment_id=D)` | `{"deploymentId": "D"}` | The deployment's backup history |
| `list_backups(deployment_id=D, status="completed")` | `{"deploymentId": "D", "status": "COMPLETED"}` | Completed backups in the history |
| `list_backups(instance_id=I)` or `list_backups(I)` | `{"instanceId": "I"}` | That instance's backups, as before |
| `list_backups(I, "completed")` | `{"instanceId": "I", "status": "COMPLETED"}` | As before |
| `list_backups(instance_id=I, deployment_id=D)` | both | The server returns `VALIDATION_ERROR`, and the SDK raises the exception it already maps that code to |
| `list_backups()` | neither | Same as above |

The SDK sends only the variables that are set. It does not check the "exactly one" rule itself (ADR-031: the server owns it).
