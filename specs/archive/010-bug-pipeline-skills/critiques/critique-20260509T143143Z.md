### 4b. Failure Mode Analysis

- 🎯 **E1 (Must-Address)**: **Lint-failure determinism gap.** FR-010 says "if those commands fail, the stage MUST surface the failure deterministically" but **does not specify which behaviour is the deterministic one**. The Edge-Cases section says "either … or … — the chosen behaviour must be deterministic". This punts the choice to implementation, which will produce different behaviour locally vs in CI, defeating SC-006. **Resolution**: pin the choice — lint failure = failure path per FR-012 (no PR opened, failure comment posted). **Applied inline** to spec.md FR-010.
- 💡 **E2**: **No concurrency control on workflows** — two `/bug-fix` invocations on the same issue race. Adding `concurrency: { group: bug-pipeline-${{ github.event.issue.number }}, cancel-in-progress: false }` is one block of YAML, has zero agent-logic content, and prevents the most obvious failure. FR-024 forbids agent logic in YAML; concurrency is workflow orchestration, not agent logic, so it's allowable. **Applied inline** to research.md §R8 (workflow YAML scope) and noted in plan project-structure section.

### 4c. Security & Privacy Review

- 💡 **E3**: **Workflow can be triggered by anyone with comment access to the repo.** GitHub's repository-level role gating is the only check; the workflow itself does not verify that the comment author has `write` (or higher) permission. The existing `claude.yml` uses the same precedent, but `bug-fix` produces code commits, raising the impact. *Mitigation deferred:* the existing `@claude` precedent is the project norm; tightening this for `bug-*` only would be inconsistent. Tracked here as a follow-up consideration.
