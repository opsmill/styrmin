## Engineering Lens Findings

### 4a. Architecture Soundness

- **E1 (🎯 — `get_client()` API break)**: Plan section "Source Code (repository root)" specifies `client.py MODIFIED — get_client() delegates to CredentialResolver; returns (client, source)`. Today every command module imports `get_client()` and does `client = get_client()`. Changing the return type to a tuple breaks every call site for a "source" value that only `whoami` consumes.
  *Suggestion*: keep `get_client() -> StyrminClient` unchanged. Add a parallel `get_auth_context() -> AuthContext` (a small dataclass with `.client` and `.source`) used only by `whoami`. `get_client()` internally calls `get_auth_context().client`. This contains the new return-shape to one caller and avoids touching `clusters.py`, `environments.py`, `drivers.py`, `deployments.py`, `backups.py`, `backup_storage_locations.py`, `tasks.py`.

### 4b. Failure Mode Analysis

- **E2 (🎯 — non-atomic save under concurrency)**: The token-store save flow described in `data-model.md` is "load → modify → write back". If two `styrminctl login` invocations run concurrently against two different servers, both reads see the same baseline, both writes happen in some order, and the later write erases the earlier one's entry. This directly contradicts FR-013 ("Tokens for distinct backends MUST coexist") and SC-005 ("Tokens for distinct backends never collide").
  *Suggestion*: specify atomic write semantics — write to `${target}.tmp.${pid}.${random}` with mode `0600`, then `os.rename()` over the target. `os.rename()` is atomic on POSIX. Add an invariant to `data-model.md` ("Save is atomic via temp-file + rename"), reflect in `contracts/login.md`, and add a unit test `test_token_store.py::test_concurrent_saves_preserve_both_entries` to the test matrix.
- **E3 (💡 — auto-login network cost)**: Rung 3 (`STYRMIN_USERNAME`+`STYRMIN_PASSWORD`) makes a `login` round-trip on every invocation. A briefly-unreachable backend in CI fails every command, not just the first. This is the right trade-off (any caching would violate FR-005 "no token persisted"), but `cli/README.md` should call it out so CI authors know to set appropriate retries/timeouts at the job level rather than expecting a built-in cache.

### 4c. Security & Privacy Review

- **E4 (💡 — `STYRMIN_PASSWORD` env-var trade-off)**: The auto-login path puts the password in the process environment, which is visible to other processes of the same user via `ps eww` on some kernels and is sometimes echoed by `set` in error logs. The trade-off is industry-standard, but the new Authentication section in `cli/README.md` should call out the alternatives (use `STYRMIN_TOKEN` from a short-lived token if the CI platform supports it; use OS-level secret injection rather than `export`) so users can make an informed choice.
- The token file lives at a predictable XDG path; `whoami` source-line discloses the path. Negligible info leak — the path is predictable from XDG anyway. No fix needed.
