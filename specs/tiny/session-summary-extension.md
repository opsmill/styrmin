## What

Add a new speckit extension `session-summary` that exposes a manual
slash command `/speckit.summary.run`. The command analyzes the
current Claude Code session and writes a single flow-level markdown
timeline (executive summary + chronological phases + outcomes) into
the **current feature directory**, alongside `spec.md` / `plan.md`,
as `sessions/session-YYYY-MM-DD-HHMM.md`. Fills the gap between
per-artifact speckit outputs and end-of-feature `speckit.archive`.

## Requirements

1. Extension directory layout matches `critique/` (extension.yml + commands/ + README.md + CHANGELOG.md + LICENSE).
2. `extension.yml` declares command `speckit.summary.run` mapped to `commands/run.md`, no `hooks:` block (manual only).
3. Extension is registered via `specify extension add <staging-dir> --dev` (NOT auto-discovered). Slash command `/speckit.summary.run` becomes invocable after install. Staging dir must live outside `.specify/extensions/` because the installer does `rmtree(dest); copytree(src, dest)`.
4. Command supports an optional `--since <commit|time>` argument to bound the window; with no argument it covers the full live session.
5. Output is a single markdown file inside the current feature directory at `specs/<feature>/sessions/session-YYYY-MM-DD-HHMM.md` (peer of `spec.md` / `plan.md`); the resolved path is printed back to the user. If no feature directory can be resolved from the current branch, fail fast with a clear error.
6. Output structure: (a) one-paragraph executive summary, (b) chronological timeline of short human-readable phases, (c) outcomes list referencing PRs/paths only.
7. Skill prompt explicitly forbids per-tool-call narration, diffs, line numbers, and code snippets longer than a one-liner.
8. README contrasts session-summary (per-session, ephemeral) with `speckit.archive` (per-feature, permanent) and `speckit.reconcile.run`.
9. `specs/<feature>/sessions/` is created on demand by the command if missing.
