# Critique Report: Environment Clone (spec.md + plan.md)

**Feature**: 010-environment-clone | **Date**: 2026-08-19 | **Reviewer**: independent dual-lens agent (Product + Engineering)

## Executive Summary

**Verdict: ⚠️ PROCEED WITH UPDATES** — applied autonomously (see Resolution Log).

The core architecture holds: every load-bearing code citation in research D2 was
spot-checked and is real and accurately line-referenced; the capture → materialise →
cross-target-restore shape, the ADR-055 derived-status reuse, and the INTERNAL-flow
justification are defensible. The Must-Address set concentrated in
derivation/deletion consistency (E2–E5, E8), one concurrency gap on the created
environment (E6), two fidelity/inventory corrections (E1, E7), and one
product-mechanism mismatch on the config override (P2). All were resolvable as
artifact edits; none required rethinking the approach.

## Product Lens Findings

- **P1 💡 Provenance one-directional, dies with source** — `environmentClones` keyed on source only; source deletion cascaded records away while created environments survive. → Keep terminal clone records with a nulled source FK; add `Environment.clonedFrom` back-reference.
- **P2 🎯 Override cannot unset scalar fields** — `update_environment_input_to_dict` omits `None` fields; scalar config (e.g. `external_dns_endpoints_type`) could only be replaced, never cleared — interference of exactly the class US3 exists to prevent. → `cloneEnvironment` gains `clearConfigFields`.
- **P3 💡 No escape pre-materialisation** — "discard via environment deletion" has no environment to delete in the post-capture/pre-materialisation window. → Escape defined via backup deletion (see E2 resolution); spec edge case updated.
- **P4 💡 Selection UX** — dialog should disable ineligible deployments with the reason, not let them silently become skips. → research D11 updated.
- **P5 🤔 No timeliness signal** — slow vs dead indistinguishable. → Resolved: UI/docs surface `createdOn`-based age; docs state expected magnitude; no SC change (duration is environment-dependent).

## Engineering Lens Findings

- **E1 🎯 "Skip apply_state" is new surgery** — `deploy_application` unconditionally calls `apply_state` (`services/deployment.py:1309`) and returns its Task; `_ensure_ingress_controller` must still reconcile. `services/deployment.py` and `services/environments.py` (clone-aware cascade) were missing from the plan inventory. → research D5 rewritten honestly; plan structure fixed.
- **E2 🎯 Permanent wedge post-capture** — flow death after a successful capture left the clone IN_PROGRESS forever with the backup un-deletable (FR-008), contradicting ADR-055 decision 6's escape philosophy. → FR-008 guard narrowed to the capture window; post-capture deletion of the backup is the documented escape (writes a fatal clone error → FAILED).
- **E3 🎯 Derivation rule 1 vs FK-nulling** — a COMPLETED clone would re-derive FAILED once its TTL'd backup was cleaned up; deleted restore rows unhandled. → derivation rewritten: fatal errors drive FAILED, backup-FK-null post-terminality preserves recorded outcomes, missing restore rows treat the entry's recorded outcome as final.
- **E4 🎯 "Null because reset" not computable** — `ON DELETE SET NULL` leaves no marker. → app-level cascade in `delete_environment` writes a `clone_errors` entry in the same transaction; derivation keys off `clone_errors`.
- **E5 🎯 PARTIAL capture gate undefined** — FR-002 only said "succeeds". → materialise iff capture ∈ {COMPLETED, PARTIAL} (matching `RESTORABLE_ENVIRONMENT_BACKUP_STATUSES`); failed-at-capture constituents attributed `failed`.
- **E6 🎯 Created environment unguarded during build** — `updateEnvironment` fan-out could race the restore flow's namespace delete-and-wait; PENDING counterparts user-deletable. → counterparts created in `RESTORING` (existing mutation guards apply); fan-out skips `RESTORING`; non-terminal clone occupies the created environment in the env-op guard; `updateEnvironment` refuses on an under-construction clone target.
- **E7 🎯 Snapshot lacks `service_name_overrides`** — FR-005 ∧ FR-007 unsatisfiable without it. → `DeploymentSnapshot` gains the field (additive JSON); counterpart creation passes it through.
- **E8 🎯 Source deletion mid-clone unspecified** — either IN_USE wedge or clone row deleted under a running flow. → source deletion handles clone records first (terminal: keep with nulled source FK; non-terminal: delete, flow tolerates NOT_FOUND), then backups; spec edge case added.
- **E9 💡 Terminality not an SQL EXISTS** — guards load candidate rows and derive in Python. → plan updated.
- **E10 💡 D1 cited PV-rename machinery our builder disables** (`restore_pvs=False`; actual mode is FSB/kopia pod-volume restore). → D1 corrected; `restorePVs` interaction recorded as a constraint.
- **E11 💡 Self-generating chart credentials** — reapply overwrites Secrets; charts minting credentials at upgrade would break restored data. → risk recorded; E2E asserts an authenticated write; docs note for driver authors.
- **E12 💡 E2E ≈2.5 clone cycles on the heaviest shard** — SC-005's re-clone trimmed to acceptance + materialisation.
- **E13 💡 Status-read query shape** — superset of the env-backup envelope; batched restore-row lookup specified.
- **E14 💡 Missing structured audit line** — `env_clone_dispatched` with outcome counters added to D4.
- **E15 🤔 Velero serialises restores** — clone duration O(N × restore); accepted at "tens of deployments" scale, recorded in plan Performance Goals.

## Cross-Lens Insights

- **X1 💡 Non-interference promise wider than the mechanism** — the override reshapes environment config only; data-borne credentials/webhooks are cloned verbatim. → honest scoping paragraph added to spec Assumptions + docs obligation.
- **X2 🤔 Ungated reads expose `configOverride`** — parity with `environmentBackup.environmentConfig` (same value class); to be recorded as a deliberate decision in the feature ADR.
