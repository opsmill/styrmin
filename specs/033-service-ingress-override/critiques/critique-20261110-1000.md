# Critique Report: Service ingress override

**Date**: 2026-11-10
**Feature**: [spec.md](../spec.md)
**Plan**: [plan.md](../plan.md)
**Verdict**: ⚠️ PROCEED WITH UPDATES

Everything below was checked against the repository at commit `5abe5647` unless marked "not verified".

---

## Executive Summary

The problem is real and the direction (Styrmin builds the Ingress of external services) fits the code: the `ingress` utility already runs for every deployment, the operator already reconciles utility objects, and the override has a natural home next to `components` in the deployment config. The spec carries the PRD faithfully and the plan has no constitution violation.

Two findings block implementation as written. First, the PRD rule for the application address (FR-002) gives the address to `task-manager` in the `infrahub` driver, where the chart's server Ingress already claims it (X1). Second, a Styrmin release that builds an Ingress for every external service changes deployments that run old driver versions, before any driver upgrade (P1). The first is fixed in the spec and plan below. The second cannot be fixed in Styrmin's own code and needs the PRD owner.
