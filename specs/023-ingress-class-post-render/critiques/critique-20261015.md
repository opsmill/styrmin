### Failure Mode Analysis

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E1 | 💡 | After the removal, an Ingress in dedicated mode has no `spec.ingressClassName`. If the cluster has a default IngressClass, the `DefaultIngressClass` admission plugin could set one on create. It does not, because it skips an Ingress that has the `kubernetes.io/ingress.class` annotation ([admission plugin, v1.35.0](https://github.com/kubernetes/kubernetes/blob/v1.35.0/plugin/pkg/admission/network/defaultingressclass/admission.go)), and Styrmin always sets the annotation in dedicated mode. The design depends on this, and the plan does not say so. Removing the deprecated annotation, which the spec puts out of scope, would break it. | Record the dependency in research D-001 and as a consequence in ADR-070. |
