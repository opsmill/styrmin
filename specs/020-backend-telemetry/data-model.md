# Data Model: Anonymous Daily Telemetry from the Styrmin Server

**Feature**: `020-backend-telemetry` | **Research**: [research.md](research.md)

One new table. The existing tables are read only. The report itself is built on demand and never stored.

## New table: `installation`

Holds the install ID. One row per database, created the first time the server starts (FR-014, research D10).

| Column | Type | Constraints | Notes |
|---|---|---|---|
| `id` | integer | primary key, `CHECK (id = 1)` named `ck_installation_single_row` | Always `1`, so a second row cannot exist. |
| `install_id` | UUID | not null | Random UUID4, generated by the server when the row is inserted. Never changes. |
| `created_on` | timestamp with time zone | not null, server default `now()` | When the row was created. Not reported. |

**SQLModel**: `Installation(SQLModel, table=True)` in `backend/styrmin_backend/db/models.py`. It does not inherit `StyrminModel` (research D10).

**Alembic**: one revision, `add_installation`, `down_revision = "c2ff6dba5ffd"`. `upgrade()` creates the table with the check constraint. `downgrade()` drops it. The revision creates no row; the server creates it on the next start.

**Lifecycle**:

- Created by `InstallationRepository.get_or_create_install_id()`: `INSERT (1, uuid4()) ON CONFLICT (id) DO NOTHING`, then `SELECT install_id WHERE id = 1`. Callers: server startup, the daily flow, `styrmin telemetry show`.
- Never updated and never deleted by Styrmin.
- A database dump restored into another install carries the same row, so both installs report the same ID (spec edge case). A database rebuilt from scratch gets a new ID.

## Existing tables read by the payload builder

| Table | Read | Query added | Used for |
|---|---|---|---|
| `cluster` | row count | `ClusterRepository.count()` | `cluster_count` |
| `environment` | row count | `EnvironmentRepository.count()` | `environment_count` |
| `deployment` | rows with `deleted_at IS NULL` | `DeploymentRepository.count_live()` | `deployment_count` |
| `applicationdriverversion` joined with `applicationdriver` and, outer, with live `deployment` rows | `applicationdriver.name`, `version`, `source_type`, count of live deployments per driver version | `ApplicationDriverVersionRepository.list_usage()` | `drivers` |

`list_usage()` returns one `DriverVersionUsage` value per driver version row:

| Field | Source |
|---|---|
| `name` | `applicationdriver.name` |
| `version` | `applicationdriverversion.version` |
| `source_type` | `applicationdriverversion.source_type` (`git`, `local`, or `internal` for the ingress controller driver) |
| `deployment_count` | `COUNT(deployment.id)` over deployments with `application_driver_version_id` equal to the row's ID and `deleted_at IS NULL`; `0` when there is none |

The query never selects `source_repository`, `source_branch`, `source_path`, `content_hash` or `source_commit_sha` (FR-002).

"Live deployment" means `deleted_at IS NULL`, the tombstone test of [ADR-008](../../dev/adr/0008-deployment-soft-delete-tombstoning.md). Internal deployments (`internal = true`, the ingress controller of each environment) are counted like the others (spec edge cases).

## Report data (not stored)

Built by `build_report_data(uow)` (research D2). The exact keys, order and value rules are in [contracts/telemetry-report-wire-format.md](contracts/telemetry-report-wire-format.md). Summary:

| Key | Type | Source |
|---|---|---|
| `install_id` | string (UUID) | `installation.install_id` |
| `styrmin_version` | string | root `pyproject.toml` `project.version`, or `"unknown"` (research D6) |
| `python_version` | string | `platform.python_version()` |
| `os_family` | string | `platform.system()` |
| `arch` | string | `platform.machine()` |
| `cluster_count` | integer | `ClusterRepository.count()` |
| `environment_count` | integer | `EnvironmentRepository.count()` |
| `deployment_count` | integer | `DeploymentRepository.count_live()` |
| `drivers` | list of objects | `list_usage()` rows merged by `(name, version, source_type)` with counts added, sorted by `name`, `version`, `source_type` (research D9) |

Validation rules:

- The key set equals FR-006 exactly. A unit test asserts it on the builder output.
- Each `drivers` entry has exactly `name`, `version`, `source_type`, `deployment_count`.
- `deployment_count` equals the sum of the `drivers` counts, because `deployment.application_driver_version_id` is a non-nullable foreign key. A unit test asserts the equality on its fixture.

## Settings (not stored in the database)

`TelemetrySettings` in `config.py` (research D7, [contracts/configuration.md](contracts/configuration.md)):

| Field | Type | Default | Source |
|---|---|---|---|
| `enabled` | bool | `true` | `STYRMIN_TELEMETRY_ENABLED` or `[telemetry] enabled` |
| `endpoint` | string | `https://telemetry-endpoints.cloudflare-096.workers.dev/styrmin` | `STYRMIN_TELEMETRY_ENDPOINT` or `[telemetry] endpoint`; blank means the default |
| `do_not_track` | string or none | none | `DO_NOT_TRACK` |

Derived: `disabled_by()` returns `"STYRMIN_TELEMETRY_ENABLED=false"`, `"DO_NOT_TRACK=1"` or `None`, in that order of precedence.
