# Critique Report: Container `command` and `args` Overrides Applied by Post-Render

**Date**: 2026-10-14
**Feature**: [spec.md](../spec.md)
**Plan**: [plan.md](../plan.md)
**Verdict**: ✅ PROCEED

---

## Executive Summary

The spec and plan follow a PRD whose decisions were taken in a review session, and they reuse a mechanism that two shipped features (env vars, ADR-057; image overrides, ADR-058) already proved. The problem is concrete: overrides that drivers do not pass to the chart are stored and never applied, with no error, and the infrahub chart cannot take a `command` at all. The design removes the cause instead of adding checks around it. The main strategic-merge assumption was checked locally on kustomize v5.7.1 during planning, and the E2E checks it on helm-controller.

No finding blocks implementation. Six recommendations sharpen what the spec promises and what the tests prove:

- scope SC-004 to the workload kinds that Styrmin patches;
- state how patch values are serialised, so a value cannot inject patch operations;
- add a test that proves SC-001 for every in-repo component, not only `simple-app`;
- list two more documentation pages;
- tell users in the migration guide that running pods keep running while the render fails;
- keep the E2E extension inside the existing test nodes.

The questions are answered from the PRD and project precedent.
