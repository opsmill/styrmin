## Executive Summary

The spec states the operator's problem from issue #39: backups have names that do not tell the operator which backup to restore. It covers the issue's acceptance criteria, with one exception, the scheduled-backup name template, which is deferred with a reason that can be checked: no code creates backups from schedules.

The plan solves the main risk in the issue. Today the Velero object name comes from the backup's name, so a rename would break restores. The plan names every new Velero object after the backup's id and keeps the stored name for objects that earlier versions created with a custom name, which ADR-073 allows. The plan reuses the existing E2E test, error classes and update-mutation pattern, and changes no Kubernetes object on a rename.

No finding blocks the work. The findings below are recommendations about downgrade behaviour, concurrent writes and test call sites.
