### Decisions and surprises the chunk agents reported

- Chunk 1:
  - `backend/pyproject.toml` has its own `[tool.ruff]` table, so the legacy driver fixtures are excluded there.
  - research.md D-014 names `tests/fixtures/legacy_drivers/`. The agent followed tasks.md: `backend/tests/functional/fixtures/legacy_drivers/`.
  - The baseline run passed: 765 tests.
- Chunk 2:
  - The code has two `ArbitrarySectionModel` classes, one for driver loading and one for the context. Research D-002 assumed one.
  - The `replicas` and `singleton` fields, the singleton check and the serializer are on a shared `ReplicaDeclaration` base class.
  - The driver content hash covers file bytes, so stored hashes do not change.
- Chunk 3: no existing test covered the removed stop-patch builder. A new test checks that a stopped component renders the same patch as before.
- Chunk 4:
  - On a version change without `input`, the stored overrides are now also checked against the target driver version. Without that check, T017's case of a component that becomes singleton would not be rejected.
  - The GraphQL `ReplicaSource` is a plain enum, because a `str` mixin loses the descriptions of its values.
  - Frontend codegen runs in a `node:22-slim` container, because it fails on host Node 18.
- Chunk 5:
  - The `ComponentConfig.replicas` and `singleton` resolvers (T035) were added early, because the create form needs them.
  - `get_deployment.graphql` also selects `componentConfigs { name replicas }`, so the drawer can show the driver default as a placeholder after the user clears the field.
- Chunk 6:
  - An E2E-only SDK operation, `get_deployment_component_replicas_full.graphql`, was added.
  - After each update, the test waits for the task to report `SUCCEEDED`, because `Deployment.status` stays `running` during an update.
  - Both variants passed on the first run.
- Chunk 8:
  - The error metadata uses `checked_against`, as contracts/errors.md says. Research D-007 uses `driver_version`.
  - When several retired values have changed, the error names the first one by name.
- Chunk 9:
  - `examples/deployments/infrahub.yml` now sets a `task-worker` replica override instead of the retired parameters.
  - Manifests merge `spec.parameters` over the stored values, and the migration guide describes this.
- Chunk 10:
  - The `styrminctl deployments get` column header is lowercase `replicas`, like the other headers. The contract says `Replicas`.
  - The CLI has a separate warning for replica overrides that do not apply.
  - Two extra labels: `1 (override, singleton)` and `, override N not applied`.
- Chunk 11:
  - The ADR is number 0070.
  - ADR-0057's wording about the stop patch is corrected.
  - `dev/knowledge/backend/services.md` no longer lists the non-existent `services/parameters.py`.
- Chunk 12:
  - Two errors in quickstart.md are fixed. The SDK and CLI tests must run in separate pytest sessions, and the singleton label is `1 (driver default, singleton)`.
  - Regenerating the schema and the generated types produced no diff.
- Review fix R1: `ComponentConfigBlock.replicas` wrote `"replicas": null` into every component override block. The agent fixed it together with H1.
- Review fix R2:
  - `ChangedFieldFrame` now keeps one wrapper while the user types. This also stops other drawer fields from losing focus, so a changelog fragment `changelog/+drawer-field-focus.fixed.md` was added.
  - The six tests of the removed `componentOverridesSchema` replica rule were deleted.
