Added per-component image overrides: a deployment can run a custom or patched build on one component, without forking its driver, by setting one image reference on that component. Styrmin applies it after the Helm chart renders, to the component container the driver declares; a `{{ app.version }}` token follows the deployment's application version, while a literal tag or digest pins the image, and both the upgrade dialog and `styrminctl deployments apply` warn about pinned overrides before an application version change. Available as `ComponentConfigInput.image` on `deploy` and `updateDeployment`, the `Deployment.componentImageOverrides` read field (stored reference, resolved reference, and whether it applies), `components[].image` in `styrminctl deployments apply` manifests, `ApplyOutcome.pinned_image_components` in the SDK, and an **Image** field per component in the deployment's Configuration editor. Invalid references, unknown components, and components without a component container are rejected before anything is deployed, and an application version upgrade that would make a stored override invalid is rejected before any lifecycle action runs.
