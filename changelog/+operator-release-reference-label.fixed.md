Fixed two passes of the operator writing different `styrmin.io/release-reference` labels on the same Ingress, Service, Secret and NetworkPolicy objects of a deployment. The HelmRelease timer used an empty release reference, because the HelmRelease that Styrmin creates has no such label, and the StyrminDeployment timer used the real one. Each timer replaced the objects that the other had written, so the label changed between the two values every few seconds. The HelmRelease timer now uses the release reference of the deployment when the HelmRelease has no label, and the builder of these objects does the same, so each object keeps one label value. The change of the label was measured on all four kinds in the end-to-end runs of the service ingress override change. Whether released versions show it for a Service, a Secret or a NetworkPolicy was not checked. In the same runs, the operator still rewrote Services about every 5 seconds, and the cause is not known.
