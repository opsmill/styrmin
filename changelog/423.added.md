Added `styrminctl clusters update`, `clusters.update()` in the SDK, the `updateCluster` GraphQL mutation and an Edit button on the cluster detail page, which administrators use to change a cluster's config without deleting and recreating the cluster, its environments and its deployments. The update replaces the whole config, requires the administrator role and is refused while an environment clone is building an environment of the cluster. Styrmin saves the new config, recomputes the cluster capabilities and redeploys each deployment, in every environment of the cluster, whose resolved config changes; a deployment in an environment that sets the changed value itself is not redeployed, and submitting the same config again redeploys only the deployments whose redeploy could not be started before. When `dedicated_ingress` changes, Styrmin moves the applications of each environment that takes the cluster's value onto the environment's ingress controller only once the controller is `RUNNING`, and removes the controller only after the applications have moved off it. `styrminctl clusters update` refuses unknown keys in the config file, and `styrminctl clusters get` and `clusters list` now print the config as JSON, so it can be copied into a file for the update.
