Fixed backups disappearing from a deployment's backup list after the deployment got a new instance. Backups taken before an upgrade, a config edit, a refresh or an environment config change now stay listed on the deployment's Backups tab and in `styrminctl backups list`, each with the application version it was taken at (a new "Application version" column on the Backups tab and `application_version` column in `styrminctl backups list`), and `styrminctl backups restore --last` chooses the newest completed one of them. API users can list a deployment's whole backup history with `backups(deploymentId:)`; `backups(instanceId:)` keeps listing the backups of one instance, and passing both arguments or neither returns `VALIDATION_ERROR`.
