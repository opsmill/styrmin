Added `styrminctl deployments scale <deployment> <component> <count>` and `client.deployments.scale()` in the Python SDK, which set or, with `--clear` or `replicas=None`, remove the replica override of one component and keep every other override of the deployment. Added the server setting `STYRMIN_MAX_REPLICA_COUNT` (Helm value `styrmin.maxReplicaCount`, default 20): a new or changed replica override above it is rejected with `REPLICA_COUNT_ABOVE_MAXIMUM` before any task starts, while a stored count sent again unchanged is kept. The review dialog of the Edit configuration drawer now lists one line per replica change, for example `server: 3 → 1 pod`. The Upgrade Deployment dialog now shows a `RETIRED_PARAMETER_VALUE` rejection with the steps that fix it on the Settings tab, a button that opens that tab and clickable links to the guides, and links in its other error messages are clickable too. The SDK and `styrminctl` now reject a replica count that is not a whole number, such as `true` or `"3"`, before they send a request.
