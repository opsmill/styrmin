Changed the agent chart to run FluxCD's helm-controller with the defaults of Helm v4 instead of the `UseHelm3Defaults` feature gate. Deployments created from this release are installed with server-side apply, and existing deployments keep client-side apply on their later upgrades and rollbacks. Installs and upgrades now wait for the chart's resources with kstatus. Helm hooks of a driver's chart, such as a pre-upgrade `Job`, now receive Styrmin's labels and, when they carry a component's identifier label, the deployment's scheduling settings, as the chart's other workloads do. A chart resource without `metadata.labels` no longer fails the install or upgrade. On a deployment installed with server-side apply, a field that the chart sets returns to the chart's value at the next upgrade, also when `kubectl` or a driver action changed it. Downgrading the agent chart to a release that runs helm-controller with the `UseHelm3Defaults` gate turns the gate on again, and deployments created in the meantime keep server-side apply. See [Operator and CRDs](https://styrmin.pages.dev/docs/concepts-and-architecture/operator-and-crds#the-helmrelease--styrmins-other-crd) and [Creating a Driver](https://styrmin.pages.dev/docs/drivers/creating-a-driver#step-1-analyse-the-helm-chart).
