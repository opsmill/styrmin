Removed the `targetNamespace` and `targetInstanceId` arguments from the `createRestore` mutation, the matching `target_namespace` and `target_instance_id` parameters from `create_restore()` in the Python SDK, and the `--target-namespace` option from `styrminctl backups restore`: Styrmin restores a backup into the deployment it was taken of, in that deployment's namespace, and records that deployment's active instance on the restore. `styrminctl backups restore` now refuses a backup id combined with `--target-deployment`, `--target-deployment-id` or `--target-instance-id`, which work only with `--last`, where they choose whose newest completed backup is restored; run `styrminctl backups restore <backup-id>` with the backup id alone. Upgrade `styrminctl`, the Python SDK and the server together, and reload web pages that were open during the upgrade: an older client sends `targetNamespace` on every restore, `--last` included, and the new server refuses it, while an older server requires `targetNamespace` and refuses a restore from a newer client. Apart from an environment clone, Styrmin offers no way to restore a backup into another deployment until deployment clone, a separate feature, ships.
