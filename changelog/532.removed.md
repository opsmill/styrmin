Removed the `targetNamespace` and `targetInstanceId` arguments from the `createRestore` mutation, the `target_namespace` and `target_instance_id` parameters from `create_restore()` in the Python SDK, and the `--target-namespace` option from `styrminctl backups restore`: Styrmin restores a backup into the deployment it was taken of, in that deployment's namespace, and records that deployment's active instance on the restore. Apart from an environment clone, Styrmin offers no way to restore a backup into another deployment until deployment clone, a separate feature, ships. Before you upgrade, read the upgrade steps under "Migration" in [A restore lands only in the deployment its backup was taken of](https://styrmin.pages.dev/docs/changelog#restores-no-longer-delete-a-namespace-that-the-caller-names): upgrade the server, `styrminctl` and the Python SDK together, reload the web pages that were open during the upgrade, remove the arguments and the option above from your scripts and requests, and run `styrminctl backups restore <backup-id>` with the backup id alone, because the command now refuses a backup id combined with `--target-deployment`, `--target-deployment-id`, `--target-instance-id` or `--environment`, which work only with `--last`.
