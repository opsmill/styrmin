Fixed renaming a backup storage location breaking it in the cluster: backups of its environments named a Velero `BackupStorageLocation` that did not exist, a credentials update failed, and unassigning the location left its Velero object and the Secret with the S3 keys in the `styrmin` namespace. Styrmin now names both objects after the location's id (`styrmin-bsl-<id>` and `styrmin-bsl-<id>-credentials`) and finds them by the `styrmin.io/bsl-id` label, so objects that earlier versions named after the location's name keep working and are updated and removed too.
