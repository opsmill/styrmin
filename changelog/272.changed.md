Changed driver loading to report the `spec.info` values that it does not store. When `spec.info.icon` is not an absolute `https` URL, or a `spec.info.links` entry does not have exactly a `link` label and an absolute `http` or `https` `url`, the load still succeeds, leaves that value out and returns a warning that names the field; neither URL can contain a username or password. The GraphQL load mutations return the warnings in the new `loadWarnings` field, `styrminctl drivers load-version` and `styrminctl drivers load-local-version` print them, and the Load driver drawer shows them in a notification. Driver files with a placeholder such as `icon: xxxx`, which the earlier `DRIVERS.md` and the Infrahub example drivers contained, still load; replace the placeholder with a logo URL, or remove the line, to stop the warning. A driver load that fails for another reason now lists one line per invalid field instead of the raw validation output.
