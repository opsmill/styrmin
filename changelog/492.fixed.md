Fixed renaming a deployment that an affinity term names: the term gave the old name, so every later update of a deployment whose term named the renamed deployment was refused with `VALIDATION_ERROR` ("Affinity deployment reference cannot be resolved"), every config fan-out redeploy in an environment whose config had such a term failed, and the rename itself was refused when the environment's config had a term that named the deployment being renamed. Styrmin now stores the id of the deployment that a term names, so a rename changes no term and restarts no pod of the deployments whose terms name the renamed deployment.
