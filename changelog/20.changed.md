Changed `get_component_images` to return the component container's image first (the other images keep their pod-template order), so a driver action that takes `images[0]` sees the component's image override; the example drivers' `upgrade` actions now do so instead of matching an image name. A driver that declares a component container name its chart does not render now fails the deployment with `COMPONENT_CONTAINER_NOT_FOUND`, naming the component and the container, as soon as env vars or an image override target that component, instead of the Helm release failing on an added container without an image; Styrmin never adds a container. Clear every image override before rolling Styrmin back below this release: older releases reject the `image` key in a deployment's config.
