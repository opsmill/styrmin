Fixed one failed item of a batch rolling back the whole batch in the cluster and environment config fan-outs and in the hooks of the deployment status report. Each item runs in its own savepoint, but when the item's code opened the unit of work twice inside that savepoint and failed, the whole transaction was rolled back. For example, a redeploy whose affinity term named a deployment that could not be found dropped the redeploys that `updateEnvironment` or `updateCluster` had already written, and a failed fan-out hook of a status report dropped the status changes that the report had already written. Now only the failed item is rolled back.
