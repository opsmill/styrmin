Added loading an application driver from a driver directory of a git repository, so one repository can hold several drivers: `styrminctl drivers load-version --driver-directory`, `driver_directory` on `drivers.load_version()` in the Python SDK, the `driverDirectory` argument of `loadRemoteApplicationDriverVersion`, the `driverDirectory` field of `ApplicationDriverVersion` and the "Driver directory (optional)" field of the "Load a driver" drawer. The driver version's Overview tab, the drivers list, the deploy form, the Upgrade dialog and the version picker of the driver page show the driver directory, and the Upgrade dialog warns when "Latest (auto)" can move a deployment to another driver directory of a driver with the same name. The driver's actions run from the driver directory and can import only modules inside it. A driver directory that starts with `/`, contains a `..` segment, a backslash, `{`, `}` or a control character, or is longer than 255 characters is refused. A reload after any commit to the repository creates a new driver version, even when the driver directory did not change. A load with a driver directory needs an upgraded Styrmin server; loads without one keep working against older servers. See [Loading a Driver](https://styrmin.pages.dev/docs/drivers/loading-drivers#loading-a-driver-from-a-driver-directory).
