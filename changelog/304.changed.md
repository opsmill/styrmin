Changed `styrminctl backups restore --last` to choose the newest completed backup from every instance of the deployment, not only from its active instance, and to skip backups whose expiry date has passed. When the chosen backup was taken of an earlier instance, the command now shows the backup's application version and the deployment's current one and asks for confirmation; `--yes` skips the question, and without a terminal the command refuses unless `--yes` is passed. The Restore dialog shows the same two versions and a warning. A restore into a deleted deployment is now refused with `OPERATION_DENIED`. The `instanceId` argument of the `backups` query is now optional; passing both `deploymentId` and `instanceId`, or neither, returns `VALIDATION_ERROR`, and the SDK raises `ValueError` before sending the request.
