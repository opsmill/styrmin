Fixed the actions of drivers loaded with `styrminctl drivers load-local-version`, which never ran: a deployment created or upgraded from such a driver now runs its setup and upgrade actions, and a hook whose declared action has no registered flow now fails with an error that tells you to load the driver again, instead of being skipped. The Styrmin agent runs these actions from the same path as the server, so a driver that only the server container holds now fails its actions with an error that names the path. Load your local drivers again after you upgrade, to register their actions. Deployments created from local drivers before this fix never ran their setup actions, and Styrmin does not run them now. Deleting a deployment whose create failed before its `StyrminDeployment` was written, for example at the setup pre-hook, now deletes it instead of returning "An internal error occurred". When an upgrade fails because an upgrade action has no registered flow, the deployment keeps its version, and `styrminctl deployments update-version` and `styrminctl deployments apply` print the error and exit with code 1, `apply --wait` included. A second `execute_commands` call on the same deployment, for example in the next upgrade with the bundled `simple-app` or `infrahub` drivers, now deletes the Job that the earlier call left and runs its commands, instead of failing because a Job of that name already exists.
