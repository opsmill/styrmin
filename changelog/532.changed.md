Changed `styrminctl backups restore --last` to treat a deployment the way the server does: `--target-deployment` and `--target-deployment-id` no longer refuse a deployment without an active instance, and `--target-instance-id` now asks for confirmation, as the deployment options already did, when the chosen backup was taken of an earlier instance of its deployment or at another application version; `--yes` skips the question, and without a terminal the command refuses unless you pass `--yes`. The Restore dialog of the web app now shows the deployment and the namespace the backup is restored into as text instead of a read-only field, and the restore warning for a deployment without an active instance no longer says that Styrmin keeps its current instance. The "Restore already in progress" error now says to wait until that restore completes or fails and where to view its status.
