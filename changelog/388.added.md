Added an `input` argument to the `updateDeploymentVersion` GraphQL mutation, with the fields of `updateDeployment`: the config, name, parameters and service name overrides it carries are checked against the target driver version and application version and written with the version in one task. It is also available as `input` on the SDK's `deployments.update_version()` and as `--config` on `styrminctl deployments update-version`, both of which need a server with this release. `styrminctl deployments apply` now warns on stderr about env vars and image overrides that it stores but that the driver version cannot apply, and the SDK returns them as `ApplyOutcome.inapplicable_components`, next to the new `ApplyOutcome.error_code`.
