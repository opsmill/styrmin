Added `error_extensions` to the outcomes of `deployments.apply()` and `apply_files()` in the Python SDK: when the server refuses a manifest, the failed outcome gives all the extensions of the error, such as the `path` of a refused affinity term, so a program that applies manifests no longer has to parse `failure_reason`. The new [Python SDK errors](https://styrmin.pages.dev/docs/reference/python-sdk-errors) page lists which exception the SDK raises for each error code and how to read these details.
