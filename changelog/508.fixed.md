Fixed one failed redeploy undoing the redeploys of the other deployments during `updateEnvironment`, `updateCluster` and `restoreEnvironmentBackup`, for example when an affinity term named a deployment that could not be found. In the two config fan-outs, a redeploy that failed while Styrmin built the new instance rolled back the whole transaction instead of only that redeploy. In an environment restore, the redeploys ran without isolation from each other, so one failure dropped the redeploys written before it, and the restore returned `INTERNAL_ERROR` although it had already reverted the environment's config. Each redeploy now fails on its own and the other redeploys are kept. The restore returns normally and writes the failure only to the server log, not on the restore record: `env_restore_fanout_dispatch_error` gives the restore id, the deployment id, the error code and the term's path, and `env_restore_fanout_dispatched` counts the failure in `config_redeploy_failed`.
