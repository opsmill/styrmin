Fixed one failed redeploy undoing the redeploys of the other deployments during `restoreEnvironmentBackup`, for example when an affinity term named a deployment that could not be found. The redeploys ran without isolation from each other, so one failure dropped the redeploys written before it, and the restore returned `INTERNAL_ERROR` although it had already reverted the environment's config. Each redeploy now fails on its own and the other redeploys are kept. The restore returns normally and writes the failure only to the server log, not on the restore record, so `styrminctl env-backups restore-get` and the UI do not list it ([#520](https://github.com/opsmill/styrmin/issues/520)): `env_restore_fanout_dispatch_error` gives the restore id, the deployment id, the error code and the term's path, and `env_restore_fanout_dispatched` counts the failure in `config_redeploy_failed`.
