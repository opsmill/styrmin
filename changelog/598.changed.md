Changed the meaning of `scope: external` for a service of a driver (breaking change). Styrmin now builds one Ingress for each external service of kind `http` or `https`. A driver that declares a service `external` and also renders its own Ingress for it gives that service two Ingresses on the same host. The effect starts when a deployment runs this Styrmin release, at its next reconcile, not only when its driver version changes. Of the drivers that OpsMill ships in `driver/examples`, only `generic-app` driver version 1 renders its own Ingress for an external service, so only deployments of that version get a second Ingress. An apply error on an Ingress now fails the deploy flow, so an ingress controller that rejects a duplicate host and path could fail the deploy flow of such a deployment. This is plausible and has not been verified. The `generic-app` driver version 2, the `infrahub` driver version 6 and the `infrahub-enterprise` driver version 5 declare an external service and render no Ingress for it, and the `task-manager` service of both Infrahub drivers is now external. When a running Infrahub deployment moves to the new driver version, the Prefect UI Ingress moves from the Helm chart to an Ingress that Styrmin builds. On a local vCluster with the operator pass every 60 seconds, the Prefect UI host answered HTTP 404 for about 7 seconds and about 12 seconds (2 samples, `infrahub-enterprise` from driver version 4 to 5). With the pass every 5 seconds, no request failed (2 samples). The length depends on when the next operator pass falls, and it was not measured on other systems or for `infrahub` version 6. A driver author removes the Ingress from the chart values of the driver, or declares the service `internal`. How many drivers outside this repository are affected is not known. See [Migrate a driver whose external service renders its own Ingress](https://styrmin.pages.dev/docs/drivers/migrating-external-service-ingress).
