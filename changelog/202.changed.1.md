Changed the upgrade and rollback requirements of Styrmin: upgrade the agent chart together with the server, because an agent from an earlier release rejects a deployment context that carries a replica override and ignores `replicas` in a driver declaration, so a component of the `infrahub` 5 or `infrahub-enterprise` 4 driver, or of any driver that moves its count to `components.<name>.replicas`, runs the chart's count without any message. Upgrade the Python SDK and `styrminctl` after the server: their `deployments get` reads `Deployment.componentReplicas` and fails against an earlier server. Clear every replica override before you roll Styrmin back below this release, because earlier releases reject the `replicas` key in a deployment's config. As soon as the server runs this release, users can set a replica override on any component of a driver version loaded earlier; if you maintain a driver, load a version that marks each single-primary component, such as a database in standalone mode, with `singleton: true` before you upgrade. See [Upgrading and rolling back Styrmin](https://styrmin.pages.dev/docs/concepts-and-architecture/replica-overrides#upgrading-and-rolling-back-styrmin).
