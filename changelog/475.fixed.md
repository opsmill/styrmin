Fixed deleting an environment or a backup storage location leaving the location's Velero object (`styrmin-bsl-<name>`) and its credentials Secret, which holds the S3 access key and secret key, in the `styrmin` namespace: Styrmin now removes them when the last environment using the location is deleted, and when the location is deleted. Deleting a location is refused with an `OPERATION_FAILED` error if the removal cannot be requested. Objects left by earlier versions stay: list them with `kubectl get backupstoragelocations.velero.io,secret -n styrmin | grep styrmin-bsl-` and delete those of locations Styrmin no longer lists.
