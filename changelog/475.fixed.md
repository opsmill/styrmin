Fixed deleting an environment or a backup storage location leaving the location's Velero `BackupStorageLocation` and its credentials Secret, which holds the S3 access key and secret key, in the `styrmin` namespace. Styrmin now removes both when the last environment of the cluster that uses the location is deleted, and when the location is deleted. Deleting a location is refused with an `OPERATION_FAILED` error when Styrmin cannot submit the removal to Prefect, and the location is kept so that you can try again. Releases up to v0.1.56 left these objects behind: list them with `kubectl get backupstoragelocations.velero.io,secrets -n styrmin -l styrmin.io/bsl-id --label-columns=styrmin.io/bsl-id` and delete those whose `styrmin.io/bsl-id` is not in the output of `styrminctl backup-locations list`.
