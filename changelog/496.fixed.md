Saving an environment or a deployment config now fails when a required node affinity term has no `matchExpressions` and no `matchLabels` entry, and the error names the term, for example `scheduling.node_affinity.required.0`. Styrmin used to save such a term. When it was the only required term, the pods could run on any node if the term had an empty `labelSelector`, and stayed `Pending` if it had an empty `matchExpressions` or `matchLabels` list. Configs saved before this change still load and deploy; fix the term the next time you save the config.
