Removed the `scheduling` setting from cluster configuration, the `scheduling` field from the `UpdateClusterInput` GraphQL input, and "Scheduling defaults" from the cluster page, which now says that scheduling is set on each environment or deployment. Styrmin stored the cluster value but never applied it to a pod. `createCluster`, `styrminctl clusters create`, `styrminctl clusters update` and `clusters.update()` in the Python SDK now refuse a cluster config that holds the `scheduling` key, whatever its value, `null` included: set scheduling on the environment or the deployment instead. `styrmin db migrate` deletes the stored values.
