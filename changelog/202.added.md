Added replica overrides: a user can now set the replica count of one component of a deployment, a whole number from 1 to 2147483647, in the Deploy form and the Edit configuration drawer, with `ComponentConfigInput.replicas` on `deploy`, `updateDeployment` and `updateDeploymentVersion` in the API and the SDK, and with `components[].replicas` in a `styrminctl deployments apply` manifest. Styrmin sets the count on `spec.replicas` of every `Deployment` and `StatefulSet` that matches the component's label selector after the Helm chart renders, so the component needs no component container and the driver needs no parameter. The count comes from the replica override, then from the driver default, then from the chart; a stopped component keeps its override and runs 0 pods until it is started, and the update task completes once the workloads report the new count of ready pods. A driver can declare a default count (`components.<name>.replicas`) and mark a component that must run a single pod with `singleton: true`, which fixes its count at 1; a driver that combines `singleton: true` with `replicas` above 1, or sets an invalid value, fails to load. The new `Deployment.componentReplicas` field in the API and the SDK reports each component's count, its source (`OVERRIDE`, `DRIVER_DEFAULT` or `CHART`), the stored override and whether it applies; the Component Overrides card on the Settings tab shows the same, `styrminctl deployments get` shows it in a new `replicas` column, and the Components tab of the driver page shows each component's default count and singleton flag (`ComponentConfig.replicas` and `ComponentConfig.singleton` in the API). Styrmin rejects a write before any task starts with `INVALID_REPLICA_COUNT` for a count below 1 (stop the component instead), with `SINGLETON_REPLICA_OVERRIDE` for a count above 1 on a singleton component, also on a change to a driver version that marks the component as singleton, and with `UNKNOWN_COMPONENT_REPLICA_OVERRIDE` for a new or changed count on a component that the driver version does not declare. An override on a component that a new driver version no longer declares is kept and not applied, and `styrminctl deployments apply` warns about it. The `simple-app` example driver moves to version 4, which marks `database` as a singleton component.
