Removed the `node_selector` setting from cluster and deployment configuration, and the `nodeSelector` field from the `UpdateClusterInput`, `UpdateDeploymentInput` and `DeploymentConfigInput` GraphQL inputs. Styrmin stored the value but never applied it to a pod. To place pods on nodes by label, set `scheduling.node_affinity` on the environment or the deployment; the [Node affinity](https://styrmin.pages.dev/docs/concepts-and-architecture/node-affinity) page shows how to convert a value such as `pool=apps`. There is no cluster-wide replacement, because Styrmin also ignores a cluster's `scheduling` value ([#482](https://github.com/opsmill/styrmin/issues/482)). `styrmin db migrate` deletes the stored values.
