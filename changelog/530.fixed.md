Fixed applications in a cloned environment that reached the source environment's deployments by short service name: the restore of each cloned deployment restored the source's service aliases, which pointed to the source environment. A clone now restores none of them and writes the aliases of the new environment, so applications in the clone reach the clone's deployments, and a deployment that was not cloned cannot be reached by short service name from the clone. A clone now also reports a deployment whose restore failed as failed, with the restore's error as the reason, where it reported it as cloned before. When a clone cannot write a deployment's service aliases, that deployment's restore fails with the error; see [Watching a clone](https://styrmin.pages.dev/docs/concepts-and-architecture/backups-and-restores#watching-a-clone-and-what-its-status-means) to write them afterwards.
