Removed the `replicas_server` and `replicas_task_worker` parameters from the `infrahub` example driver (version 5) and the `infrahub-enterprise` example driver (version 4): set a replica override on the `server` or `task-worker` component instead. A deployment that stores either parameter at its old default (`1` and `2`) moves to the new versions without a manual step. A deployment that stores another value is rejected with `RETIRED_PARAMETER_VALUE` until the same request, or an earlier one, carries the value over as a replica override and resets the parameter to its default. This includes every deployment created from the earlier `examples/deployments/infrahub.yml` manifest, which set `replicas_task_worker: 1`. See [Migrating Replica Parameters](https://styrmin.pages.dev/docs/drivers/migrating-replica-parameters#deployments-created-from-the-earlier-example-manifest).
