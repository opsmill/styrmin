Changed the `infrahub` and `infrahub-enterprise` example drivers to versions 5 and 4, which remove the `replicas_server` and `replicas_task_worker` parameters: `server` and `task-worker` now have driver defaults of 1 and 2 replicas, the defaults of the old parameters, and `database`, `task-manager-db` and `cache` are singleton components. Changed what happens to a parameter that the target driver version no longer declares when a deployment changes driver version: a stored or submitted value that equals the parameter's default in the current driver version, with the same type, is now dropped, so a deployment that kept the defaults moves to the new infrahub driver versions without a manual step; any other value now rejects the change with `RETIRED_PARAMETER_VALUE`, which names the parameter and its value and links the guide that explains how to carry a replica count over as a replica override, instead of `OPERATION_FAILED` "Unknown parameter". A driver version that declares `components.<name>.replicas`, including one loaded before this release, now has that count applied as the component's driver default. Upgrade the agent chart together with the server: an earlier agent rejects a deployment context that carries a replica override. Clear every replica override before rolling Styrmin back below this release: earlier releases reject the `replicas` key in a deployment's config.
