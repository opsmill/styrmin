Changed the `infrahub` and `infrahub-enterprise` example drivers to versions 5 and 4, which remove the `replicas_server` and `replicas_task_worker` parameters: `server` and `task-worker` now have driver defaults of 1 and 2 replicas, the defaults of the old parameters, and `database`, `task-manager-db` and `cache` are singleton components. Changed what happens to a parameter that the target driver version no longer declares when a deployment changes driver version: a stored or submitted value that equals the parameter's default in the current driver version, with the same type, is now dropped, so a deployment that kept the defaults moves to the new infrahub driver versions without a manual step; any other value now rejects the change with `RETIRED_PARAMETER_VALUE`, which names the parameter and its value and links the guides that explain how to fix it and how to carry a replica count over as a replica override, instead of `OPERATION_FAILED` "Unknown parameter". A request or manifest that still sets a parameter the deployment's driver version no longer declares fails with "Unknown parameter", as before, and the message now links the [Changing Driver Versions](https://styrmin.pages.dev/docs/drivers/changing-driver-versions) page, which describes the rule for every driver. A driver version that declares `components.<name>.replicas`, including one loaded before this release, now has that count applied as the component's driver default.
