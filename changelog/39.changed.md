Velero `Backup` objects for new backups are now always named `styrmin-<backup id>`, even when the backup has a custom name, so a rename changes no object in the cluster. Scripts that look up a Velero backup by its Styrmin backup name must use the backup id instead. Backups created earlier with a custom name keep their Velero object. Backup names are now unique among the backups of one deployment instance instead of across all backups.
