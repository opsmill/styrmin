Fixed `styrminctl deployments apply` checking component config against the driver version a deployment moves away from. For an existing deployment, `apply` now sends the config, parameters and version in one request, so the config is checked against `spec.version` and the newest loaded driver version that supports it, one task reconciles the change, and a rejected apply leaves the deployment unchanged and is reported as `failed` with the server's error code. A manifest can now move a deployment onto a driver version that declares component containers and add component env vars in the same apply. Upgrade the Styrmin server before or together with `styrminctl` and the SDK: against an older server, `apply` fails with a message that says to upgrade the server.
