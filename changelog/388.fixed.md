Fixed `styrminctl deployments apply` checking component config against the driver version a deployment moves away from. For an existing deployment, `apply` now sends the config, parameters and version in one request, so the config is checked against the driver version the manifest declares, one task reconciles the change, and a rejected apply leaves the deployment unchanged. A manifest can now move a deployment onto a driver version that declares component containers and add component env vars in the same apply. The `updateDeploymentVersion` GraphQL mutation and the SDK's `deployments.update_version()` accept an `input` with the fields of `updateDeployment` for this.
