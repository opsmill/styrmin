Fixed the `backup.velero.storage_location` capability of an environment that has a backup storage location: it held the location's name, which no Velero `BackupStorageLocation` has. It now holds the name of the location's Velero object, `styrmin-bsl-<location id>`, which does not change when the location is renamed. `styrmin db migrate` updates the stored values, and a deployment's context gets the new value the next time Styrmin redeploys it.
