Removed the `component_command` and `component_args` driver template filters. Loading a driver version whose `values.j2.yml` calls either one, or the earlier retired `component_env_vars`, now fails with `RETIRED_TEMPLATE_FILTER` and an error that names the line and the [migration guide](https://styrmin.pages.dev/docs/drivers/migrating-container-overrides). A driver version loaded earlier that still calls them fails rendering with the same error, also when no override is set, so a deployment pinned to it fails on its next change until it moves to a migrated driver version; its pods keep running meanwhile. Removed `spec.container_overrides` from the driver specification file (a `driver.styrmin.yml` that still contains it fails to load with an error that links the migration guide), from the stored driver version (a database migration drops the column) and from the API and SDK: `ApplicationDriverVersion.containerOverrides`, the `DriverContainerOverrideDoc` type, the SDK's `get_driver_container_override_docs` method and the `DRIVER_CONTAINER_OVERRIDE_DOC_COMPONENT_MISMATCH` error code. Before you upgrade Styrmin, list the stored `command` and `args` overrides of your deployments with `styrminctl deployments get` and remove the values you do not want with `styrminctl deployments update --config` or `styrminctl deployments apply`; the Configuration editor of earlier releases cannot submit a change that only removes them. After the upgrade, Styrmin applies them to every component with a component container on the next render of the deployment, which an env var edit on its environment or a cluster config update can also start, so values that a driver template did not pass to the chart reach the pods for the first time: `command` on the infrahub `server`, for example, and every value on a driver whose template never called the filters, such as `slurpit`, `semaphore`, `infrahub-mcp` and `db-test`. See [Before you upgrade Styrmin](https://styrmin.pages.dev/docs/drivers/migrating-container-overrides#before-you-upgrade-styrmin).
