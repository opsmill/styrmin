Fixed `execute_commands` failing with `Job <release>-job already exists` on the second call in a deployment namespace (for example the second upgrade of the same deployment, including the bundled Infrahub migration step): every call now creates a uniquely named Job, finished Jobs are garbage-collected by Kubernetes after one hour, and a name conflict or failed Job is raised as a typed `JobAlreadyExistsError` / `JobFailedError`.
