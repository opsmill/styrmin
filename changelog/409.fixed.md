Fixed the dedicated ingress setting being read two ways: an empty `dedicated_ingress` (`{}`) now deploys the per-environment ingress controller with default values, as it already did for the application Ingress. A cluster created without `dedicated_ingress` no longer stores `{}`, and the database upgrade removes the `{}` that existing clusters stored, so their deployments keep running without a dedicated controller and their Ingress now uses the cluster `ingress_class`.
