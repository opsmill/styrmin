Fixed Velero backup-repository maintenance, which had never run in any Styrmin install: Velero resolves its own Deployment by the hardcoded name `velero` to build the kopia maintenance Job, but the `velero` subchart named it `<release>-velero`, so every cycle failed with `Deployment.apps "velero" not found`, kopia never pruned, and the data behind expired backups was never reclaimed from the bucket. `helm/styrmin/values.yaml` now pins `velero.fullnameOverride: velero`. **Upgrading:** the Velero Deployment, Service, ServiceAccount, and ConfigMaps are renamed, so `helm upgrade` replaces them and the Velero pod restarts once; update anything referring to the old names (`deployment/<release>-velero`, dashboards, scrape configs) to `velero`. The PVC-patch ConfigMap is now `velero-restore-pvc-patch`; Restores created before the upgrade keep pointing at the old name and cannot be re-driven, but Restores are one-shot objects and new ones are unaffected.
