Changed how container `command` and `args` overrides reach pods: Styrmin now applies them after the Helm chart renders, to the component container the driver declares (`components.<name>.container`), together with env vars and image overrides, so a driver no longer passes them to the chart in `values.j2.yml`. An override replaces the whole `command` or `args` list, a field without an override keeps the value the chart renders, clearing an override brings back the chart's `command` and `args`, and overrides no longer reach chart Jobs, init containers or other containers in the pod. The `server` and `task-worker` components of the `infrahub` and `infrahub-enterprise` example drivers now accept `command`, and the `simple-app`, `infrahub` and `infrahub-enterprise` example drivers move to versions 3, 4 and 3. Adding or changing `command` or `args` on a component without a component container is now rejected with `COMPONENT_CONTAINER_NOT_DECLARED` (metadata `override` set to `command` or `args`); removing a stored value, or sending the same value again, is still accepted. The deployment's Configuration editor hides the Command and Args editors for such a component and shows stored values read-only, marked "not applied", with a remove button, and the new `ComponentContainerOverrides.isApplicable` field in the API and the SDK reports whether a stored override applies.
