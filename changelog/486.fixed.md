Fixed required node affinity of an environment and a deployment: a pod now runs only on a node that matches a required term of both, instead of on a node that matches the terms of either one. A running deployment where both set required terms gets the combined terms the next time Styrmin redeploys it, which includes a change to its environment's config and any update of its cluster, even one that changes an unrelated value; run the cluster update with `--dry-run` first to list the deployments it redeploys. When the two levels' terms cannot be met together, for example `pool=apps` on the environment and `pool=db` on the deployment, Styrmin saves the config without a warning and the redeployed pods stay pending: set `replace: true` in the deployment's `nodeAffinity` block, or change the environment's terms.
