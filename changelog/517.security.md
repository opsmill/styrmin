Stopped loads from git from reading files outside the cloned repository. Before, a repository whose `driver.styrmin.yml`, `values.j2.yml` or `actions.py` was a symlink to a path on the Styrmin server, such as `values.j2.yml -> /etc/...`, made the server read that file and return it in the driver version, for example in `helmChart.valueTemplate`. Every load from git, also from the repository root, now fails when the driver directory is a symlink to a path outside the repository, when one of these three files is a symlink to a path outside its driver directory (the whole repository for a load from the root), or when one of them cannot be followed, such as a symlink loop. Reloading a repository that has such a symlink now fails with a message that names the file; replace the symlink with the file it points to. Error messages of git loads no longer show the user info, such as `user:token@`, of any URL that a clone error repeats. See [Loading a Driver](https://styrmin.pages.dev/docs/drivers/loading-drivers#refused-driver-directories-and-error-messages).
