Changed `updateDeploymentVersion`, which the upgrade dialog, `styrminctl deployments update-version` and driver actions use, to recreate a deployment's services before it generates the new instance, and only when the driver version or a service name changes: a values template that reads `services` now gets the target driver version's services in the upgrade itself instead of one reconcile later. A call that keeps both the application version and the driver version now shows as an update in the deployment timeline instead of an upgrade. `styrminctl deployments apply` now rejects component config on a component that the target driver version does not declare even when the config is unchanged, so remove that config from the manifest in the same change that moves `spec.version`. The SDK's `deployments.apply()` now returns a `failed` outcome instead of raising when the server rejects the manifest. The errors for component overrides on an unknown component or a component without a component container now name the driver, driver version and application version that were checked.
