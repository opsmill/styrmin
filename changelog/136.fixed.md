Fixed the backup size (`sizeBytes` in GraphQL, `size_bytes` in the SDK and `styrminctl backups`, and the size column in the web UI) holding a count of Velero item operations instead of bytes. A completed backup now records the bytes of volume data that Velero read, before deduplication and compression, and the size stays empty when the backup captured no volume data. To hold sizes above 2 GiB, `sizeBytes` now uses a new `BigInt` GraphQL scalar (a JSON number) instead of `Int`, and a database migration widens the `backup.size_bytes` column to `BIGINT`. The Helm charts now grant read access to Velero `podvolumebackups`.
