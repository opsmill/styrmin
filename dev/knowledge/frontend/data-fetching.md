## Frontend Data Fetching

### Overview

The frontend uses **TanStack Query** as the GraphQL data layer. Typed `useQuery` and `useMutation` hooks are generated by `@graphql-codegen/typescript-react-query` from `.graphql` operation files. There is no GraphQL client library between the codegen output and the network — the fetcher is a thin wrapper around native `fetch`.

See [ADR-011](../../adr/adr-011-replace-urql-with-tanstack-query.md) for the migration rationale.

### Codegen Pipeline

```text
frontend/src/graphql/*.graphql
        │
        │  pnpm codegen   (config: frontend/codegen.ts)
        ▼
frontend/src/generated/graphql.ts    # single output file: typed useXxxQuery / useXxxMutation
                                     # hooks + getKey query-key factories (exposeQueryKeys: true)
```

Operation files are unchanged from the urql era. Codegen produces hooks named after each operation (`GetCluster` → `useGetClusterQuery`) plus a static `getKey({ id })` query-key factory used for cache invalidation. The plugin set is `typescript` + `typescript-operations` + `typescript-react-query` (with `reactQueryVersion: 5`).

### Query Client

A single `QueryClient` is created in `src/lib/query-client.ts` and provided at the app root (in `App.tsx`) via `<QueryClientProvider>`.

```ts
new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 0,                  // urql-equivalent: always re-validate on mount
      gcTime: 5 * 60_000,            // 5 min before unused cache is collected
      retry: 3,                      // exponential backoff
      refetchOnWindowFocus: true,
    },
    mutations: {
      retry: 0,                      // never retry mutations blindly
    },
  },
});
```

### Fetcher

The codegen `fetcher` config points at `src/lib/graphql-fetcher.ts`, which POSTs `{ query, variables }` to `/graphql` with native `fetch` and returns `data` — or throws. Error handling distinguishes two failure modes:

- **`GraphQLTransportError`** (custom class, exported): non-2xx HTTP, missing/unparseable body, or `data === undefined` on a 2xx. Carries `status`, `statusText`, and the raw body for diagnostics.
- **`Error`** (plain): a 2xx response with a populated `errors` array — message taken from the first error.

There is no `graphql-request` dependency.

### Cache Invalidation

Mutations declare invalidation in their `onSuccess`. The query-key factory generated for each operation makes broad and targeted invalidation symmetric.

```ts
const createCluster = useCreateClusterMutation({
  onSuccess: () => {
    queryClient.invalidateQueries({ queryKey: useListClustersQuery.getKey() });
  },
});
```

- `useListClustersQuery.getKey()` invalidates **every** active `ListClusters` query, regardless of variables.
- `useGetClusterQuery.getKey({ id })` invalidates one cluster by id.

Direct `setQueryData` is intentionally not used — server response shapes vary, and duplicating server logic client-side is brittle.

### Conditional Fetching

`enabled: cond` replaces urql's `pause: !cond`. Only two call sites use it (both in `DeploymentDetailPage`).

```ts
useGetDeploymentQuery({ id }, { enabled: !!id });
```

### Auto-Refresh / Polling

Per-query `refetchInterval` replaces the previous custom `useAutoRefresh` hook. Polling automatically pauses on hidden tabs (`refetchIntervalInBackground: false` is the default).

```ts
useGetDeploymentQuery({ id }, { refetchInterval: 3000 });
```

### DevTools

`@tanstack/react-query-devtools` is mounted lazily and gated by `import.meta.env.DEV`, so it is excluded from production builds.

### Test Utilities

`frontend/src/test/utils.tsx` constructs a per-test `QueryClient` with retries off and gc off, wrapped in `<QueryClientProvider>`. This avoids cache pollution between tests and keeps assertions deterministic.

### Route-Level Loading (Deferred)

TanStack Router's `loader` + `queryClient.ensureQueryData` integration is **not** in use today — the migration kept component-level fetching to bound scope. Adding route loaders is a separate architectural change, evaluated independently.

### What Was Replaced

| Concept | Before (urql) | After (TanStack Query) |
|---------|---------------|------------------------|
| Hook generation | `@graphql-codegen/typescript-urql` | `@graphql-codegen/typescript-react-query` |
| Transport | `@urql/core` exchanges | native `fetch` wrapper |
| Conditional fetch | `pause: !cond` | `enabled: cond` |
| Cache invalidation | manual `reexecute({ requestPolicy: 'network-only' })` per consumer | `queryClient.invalidateQueries({ queryKey })` in mutation `onSuccess` |
| Polling | custom `useAutoRefresh` hook | per-query `refetchInterval` |
| DevTools | none | `@tanstack/react-query-devtools` (dev-only) |
